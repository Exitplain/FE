# 실제 작업을 따라가는 첫 테스트 안내

- 시작 가이드의 **튜토리얼 다시 보기** 또는 `/guide?tutorial=1`에서만 수동으로 시작합니다. 첫 방문·첫 로그인에는 자동 제안이나 시작 팝업이 없습니다.
- 새 프로젝트 열기 → 실제 등록 폼 → 프로젝트의 새 테스트 시작 → 사이트 확인 → 과업·타겟 → 페르소나 설정 → 시작 전 확인 → 생성된 페르소나 확인 순서입니다.
- 안내 전용 다음 버튼이나 임의 데이터가 없습니다. 기존 폼의 검증과 실제 API 응답으로 화면이 바뀔 때 해당 화면의 설명이 나타납니다. 오류나 로딩에서 다음 단계를 가정하지 않습니다.
- 직접 누른 프로젝트 등록·사이트 탐색·설정 저장·페르소나 생성은 기존 API로 실제 처리됩니다. 튜토리얼 자체는 이 요청들을 호출하지 않습니다.
- 생성된 페르소나가 표시된 후 **준비 안내 마치기**는 안내만 종료합니다. **실행 시작**은 기존 버튼을 사용자가 직접 눌러야 합니다. 사용자가 안내를 닫지 않고 실행 화면으로 이동해도 안내는 종료됩니다.
- 준비 안내를 마친 계정은 해당 프로젝트의 리포트 데이터를 받았을 때 짧은 결과 읽기 안내를 봅니다. 확인 후 반복하지 않습니다. 서버 데이터를 추가하거나 수정하지 않습니다.
- 실제 버튼·폼·페르소나 영역을 밝게 남기고 주변을 어둡게 표시합니다. 흰 말풍선과 화살표를 대상 옆에 배치하고 창 크기 변경·스크롤·내용 변경에 맞춰 위치를 다시 계산합니다. 넓은 폼 옆에는 사이드바 공간을 활용합니다.
- 폼 옆 공간이 부족한 좁은 화면에서는 폼 위의 흐름 안에 안내를 배치해 입력칸과 제출 버튼을 덮지 않습니다.
- 안내는 입력을 덮어쓰거나 화면을 강제로 이동시키지 않습니다. 시각적 덮개는 포인터 입력을 가로채지 않아 기존 버튼·입력창을 조작할 수 있습니다. 안내 접기는 덮개도 숨기며 입력과 폼을 유지합니다. 별도의 배경 잠금과 초점 가두기는 추가하지 않습니다.
- `OnboardingHint`는 실제 화면 내부에 삽입됩니다. 등록 모달 내부 안내도 기존 모달의 키보드·초점 동작을 그대로 따릅니다. 공통 폼/API 로직은 변경하지 않습니다.
- 계정별 완료 기록과 리포트 도움말 기록은 localStorage에 저장합니다. 진행 중인 튜토리얼은 메모리에서만 유지하며 로그인·새로고침 후 자동 재개하지 않습니다. 이전 버전의 저장된 진행 기록도 무시합니다. 수동 시작 후에는 실제 작업 화면을 이동하면서 안내가 이어집니다.
- 문구: `src/constants/onboarding.ts`, 화면별 안내: `OnboardingHint.tsx`, 강조·말풍선 배치: `Coachmark.tsx`, 시작 가이드 링크 처리: `OnboardingHost.tsx`.
