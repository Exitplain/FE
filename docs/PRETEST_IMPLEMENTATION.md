# 사전 테스트(P01~P11) 구현 정리

작성일: 2026-11-13 · 대상: `web/` · 기준 Figma: [4호선톤 와이어프레임](https://www.figma.com/design/XYkGMN8Avldbl3SN65vEsr) `IA — 전체 플로우`(114:18550)

Figma IA의 사전 테스트 흐름(테스트 목록 → 새 테스트 → 실행 → 세션 라이브)을 `web/`에 구현한 기록입니다. BE 개발 API가 지원하는 범위, mock으로 동작시킨 범위, 화면만 만든(퍼블리싱) 범위를 화면별로 나눴습니다. 이어서 작업하는 사람이 "왜 Figma와 다른지"를 여기서 확인할 수 있게 하는 것이 목적입니다.

## 1. 흐름과 경로

```
프로젝트 ─[사이드바 테스트]→ P01 테스트 목록 (E02 빈 상태)
P01 ─[새 테스트 시작하기]→ P02 사이트 → P03 확인 완료 ─┬[테스트 계정 등록]→ P04 모달
                                                     └[다음]→ P05 과업·타겟 → P05b 페르소나 → P05c 시작 전 확인
─[실행 시작]→ P08 준비 → P09 실행 중 ─[타일]→ P11 세션 라이브
                                   └(끝나면) 완료 요약 ─[리포트 보기]→ P12 리포트 (별도 작업)
```

| 화면               | 경로                                                               | 폴더                                        |
| ------------------ | ------------------------------------------------------------------ | ------------------------------------------- |
| P01, E02           | `/projects/:projectId/tests`                                       | `pages/test-list`                           |
| P02~P05c, E07, E08 | `/projects/:projectId/tests/new?step=site\|task\|persona\|confirm` | `pages/new-test`                            |
| P08~P10, E05, E12  | `/projects/:projectId/runs/:runId?task=&filter=`                   | `pages/test-run`                            |
| P11                | 같은 경로 + `&session=<세션ID>`                                    | `pages/test-run/components/SessionLive.tsx` |

- 경로 문자열은 `constants/routes.ts`에만 있고, 이동 주소는 `buildPath(key, params)`로 만듭니다. 파라미터가 빠지거나 이름이 틀리면 타입 오류가 나고, 빈 값은 예외가 납니다.
- 사전 테스트 경로는 Figma에서 모두 프로젝트 탭 안의 화면이라 `/projects/:projectId/...` 아래에 둡니다. BE 실행에는 프로젝트 정보가 없어서 `projectId`는 화면 문맥(경로 표시·탭·사이드바)에만 씁니다.
- 사이드바: 프로젝트 화면에서 하위 메뉴(테스트·진단 기록·발견한 문제)를 펼칩니다. 테스트 목록·실측 분석·보정 탭과 사전 테스트 흐름은 하위 "테스트"를, 프로젝트 개요만 프로젝트 항목을 선택 표시합니다. 진단 기록·발견한 문제는 프로젝트 전용 경로(`/projects/:projectId/history`·`/issues`, C08·C09, 빈 페이지)로 연결합니다.

## 2. 화면별 구현 범위

표기: **동작** = BE 개발 API 계약대로 동작(테스트·dev:mock은 MSW) · **로직** = 서버 없이 화면에서 완성 · **퍼블리싱** = 서버 기능이 없어 화면만 · **없음** = 만들지 않음

| 화면                            | 범위                | 내용 · Figma와 다른 점                                                                                                                                                                               |
| ------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P01 목록                        | 동작                | 완료 실행(`GET /api/personas/reports`) + 진행 중 실행(`GET /api/personas`). 이름은 API에 없어 `N차 · 문제/개선 버전 · 세션 N개`, 목표 달성률은 `—`. "실패" 상태는 목록 API가 완료만 줘서 나오지 않음 |
| E02 빈 상태                     | 동작                | 완료·진행 실행이 모두 없을 때                                                                                                                                                                        |
| P02 사이트                      | 동작 + 퍼블리싱     | 사이트 확인 = `POST /api/personas/discover`. 서버가 URL 대신 반찬 데모 버전(`variant`)만 받아 **입력한 URL은 아직 탐색에 쓰지 않음**. 데모 버전 선택(문제/개선)을 추가                               |
| P02b 확인 중                    | 동작                | 확인하는 동안 주소·버전 잠금                                                                                                                                                                         |
| P03 확인 완료                   | 동작                | 응답 시간·화면 수는 응답에 없어 "기능 N개 · 과업 N개"로 표시                                                                                                                                         |
| E07 잘못된 URL                  | 로직                | 주소 모양만 검사(`validateSiteUrl`)                                                                                                                                                                  |
| E08 접근 불가                   | 동작                | discover 503                                                                                                                                                                                         |
| P04 테스트 계정 (b·c·d)         | 퍼블리싱            | 직접 입력·붙여넣기·중복 검사·최대 20개까지. **서버에 로그인 연결이 없어 저장만 하고 실행에는 안 씀**. 원격 브라우저 단계, P04c 로그인 확인, E13 없음                                                 |
| P05 과업·타겟                   | 동작                | 기능별 과업(근거 경로), 추천 과업 미리 선택. 직접 추가한 과업은 BE가 실행하지 못해 제외. 메모는 `additional_request`로 기록만                                                                        |
| P05a 선택 전                    | 로직                | 과업 0개·타겟 비움이면 다음 불가, 오류로 초점 이동                                                                                                                                                   |
| P05b 페르소나                   | 퍼블리싱(읽기 전용) | BE 고정 프로필 3개 × 과업 = 세션 수. **세그먼트 +/- 편집, P05e 합계 오류, P05h 없음**                                                                                                                |
| P05c 시작 전 확인               | 동작                | 요약 + 단계별 변경 링크. 버튼은 "페르소나 생성" 대신 **"실행 시작"**(BE confirm이 바로 실행 시작)                                                                                                    |
| P06 생성 중 · P07 페르소나 확인 | 없음                | confirm이 생성과 실행을 나누지 않음                                                                                                                                                                  |
| P08 실행 준비                   | 동작                | 준비 단계 정보가 없어 세션 상태로 계산(프로필 불러오기 → 브라우저 준비 k/N → 첫 세션 시작)                                                                                                           |
| P09 실행 중                     | 동작                | 과업 탭, 진행 n/N, 경과 시간, 가장 많은 단계, 최근 끝난 세션, 상태 필터, 세션 타일. **Think-aloud 자리에 세션별 마지막 행동 기록**(BE가 발화를 만들지 않음)                                          |
| P09b 타일 미리보기              | 동작(타일에 포함)   | 현재 단계·스텝을 타일에 함께 표시. 별도 미리보기 팝업 없음                                                                                                                                           |
| P10 분석 중                     | 없음 → 완료 요약    | BE가 리포트를 요청할 때 계산해 분석 단계가 없음. 끝나면 결과 요약 + "리포트 보기"                                                                                                                    |
| P11 세션 라이브                 | 동작                | 현재 단계·스텝·좌절 점수·결과, 행동 로그. 라이브 화면은 다른 출처의 원격 브라우저 주소일 때만 iframe(개발 환경), 아니면 마지막 스크린샷. 토큰·비용은 BE에 없음                                       |
| E05 실행 실패                   | 동작                | 모든 세션이 실행 오류·한도 도달로 끝났을 때                                                                                                                                                          |
| E12 한도 도달                   | 동작                | `budget_exceeded` 세션을 "한도 도달"로 표시하고 오류로 셈(이탈률에 넣지 않음)                                                                                                                        |

## 3. 데이터와 상태

| 구분                | 위치                         | 비고                                                                                                         |
| ------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| API 함수            | `apis/persona.api.ts`        | `getPersonaRun`, `discoverPersonaPlan`, `confirmPersonaRun`, `getPersonaReports`, `explainPersonaSession`    |
| 타입                | `types/persona.type.ts`      | BE 실제 응답 기준. idle 상태에 없는 키는 선택(`?`)                                                           |
| 현재 실행           | `hooks/usePersonaRun.ts`     | running일 때만 2초 polling. running → completed가 되면 목록 다시 조회                                        |
| 완료 목록           | `hooks/usePersonaReports.ts` |                                                                                                              |
| 위저드 입력         | `stores/useNewTestStore.ts`  | zustand, **persist 없음**(비밀번호를 저장소에 남기지 않음). 화면을 떠나거나 "로그인 없이"로 바꾸면 계정 삭제 |
| 실행 화면 과업·필터 | 주소 `?task=`, `?filter=`    | 세션 라이브에 갔다 와도 유지                                                                                 |

오류 처리

- confirm 400: 메시지에 "만료"가 있으면 사이트 단계로 되돌리고, 그 밖의 입력 오류는 확인 화면에 표시
- confirm 409: 현재 실행을 다시 받아 "실행 화면 보기" 링크
- 탐색 계획은 15분 뒤 만료: 확인 화면에서 시간이 되면 안내, 실행 직전에 다시 확인
- polling 중 실패: 받아 둔 화면은 두고 "최신 상태를 불러오지 못했어요" + 다시 시도
- BE는 현재 실행 하나만 조회할 수 있어, 주소의 `runId`가 현재 실행이 아니면 완료 목록에 있으면 리포트로, 없으면 목록으로 안내

## 4. mock (BE 없이 실행)

`npm run dev:mock`이면 `mocks/personaMock.ts`가 BE 개발 API를 메모리 상태로 흉내 냅니다.

- 탐색 → 확인(BE와 같은 검증 규칙) → `GET /api/personas` 호출마다 한 단계 진행(동시 3세션) → 완료 → 목록·질문
- 세션 결과는 정해 둔 예시: 빠른 구매 = 이탈, 여유 있는 탐색의 배송 지역 확인 = 실행 오류, 나머지 = 완료
- 오류 재현: `handlers/personas.ts`의 `personaErrorHandlers` (503, 400 만료, 409, 네트워크 오류, 빈 목록)
- 주의: 진행은 시간이 아니라 조회 횟수 기준이고, 새로고침하면 mock 상태가 사라집니다. 실제 BE는 시작할 때 최근 완료 실행을 복원해 첫 조회부터 `completed`일 수 있습니다.

## 8. 남은 일과 확인할 것

BE에 확인·요청할 것

- 사용자가 입력한 URL 탐색(P02·P03), 응답 시간·화면 수
- 테스트 계정 로그인 연결(P04 원격 브라우저·lease·로그인 확인, E13)
- 세그먼트 수·비율 조정(P05b·P05e·P05h), 페르소나 생성과 실행 시작 분리(P06·P07)
- 실행별(`runId`) 진행 조회, 목록 응답의 이름·차수·목표 달성률·실패 상태
- Think-aloud 발화, 세션 종료 시각, 토큰·비용(P09·P11)

프론트에서 이어서 할 것

- P12 리포트(완료 요약의 "리포트 보기"가 연결되는 화면), P15 세션 상세
- C08·C09 프로젝트 진단 기록·발견한 문제 화면(경로·빈 페이지만 있음)
- 위 BE 기능이 생기면 퍼블리싱 화면(P04, P05b)을 실제 동작으로 연결하고 이 문서의 표를 갱신
- 단일 선택 칩·필터의 방향키 이동(radiogroup 키보드 패턴)
