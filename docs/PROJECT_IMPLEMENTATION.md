# 프로젝트 화면 구현

기준 브랜치: `project` · 분기 커밋: `login`의 `9eece63` (`feat: 로그인 및 워크스페이스 화면 구현`). 프로젝트 작업은 별도 커밋 전 상태로 유지합니다.

## 범위

- C02·C02b: 프로젝트 이름·URL 검색, 목록·검색 결과 없음, 행 클릭으로 개요 이동
- C03·C04·C04b: 이름·URL·고객 여정 입력, 검증·중복 사이트 검사, 생성·취소
- C05·C06: 진단 루프, 최근 사전 테스트·실측·보정 요약, 관련 화면 이동
- C08·C09: 해당 프로젝트의 진단 기록·발견한 문제만 표시

화면 전용 컴포넌트는 각 페이지의 `components/`, 프로젝트 공용 헤더·생성 모달·안내는 `components/Projects/`로 분리합니다. 생성 폼 상태·검증·저장 요청은 `components/Projects/hooks/useProjectForm.ts`에 둡니다. 워크스페이스 기록·문제 화면은 선택적 `projectId`·`header`로 재사용합니다. 인자가 없는 기존 워크스페이스 화면은 전체 데이터를 계속 표시합니다.

## 데이터·API 교체 위치

- `types/project.type.ts`: 입력·프로젝트 목록·개요 데이터 계약
- `apis/project.api.ts`: 목록·개요 조회와 생성 함수. 현재 독립된 더미 저장소이며 이후 서버 API로 교체
- `mocks/fixtures/projects.ts`: C05·C06 및 다른 샘플 프로젝트의 테스트·실측·보정 데이터. 수치를 화면 코드에 직접 넣지 않음
- `hooks/useProjects.ts`: 목록·개요 조회·생성 mutation과 캐시 갱신. 목록의 `initialData`는 데모용이므로 실제 API 연결 시 제거하거나 서버 초기값으로 교체
- `utils/projectRegistry.ts`: `exitplain-project-demo-records` 키로 탭의 sessionStorage에 새 프로젝트 저장
- `utils/projectInput.ts`: HTTP·HTTPS 주소, 필수 입력값 검증

같은 origin의 사이트는 중복 등록할 수 없습니다. 고객 여정은 프로젝트 정보로 저장하며 실제 탐색·과업 생성 API에 전달하는 작업은 후속 연동 범위입니다. 기존 데모 테스트 실행은 원래의 반찬 쇼핑몰 variant를 사용하며 입력한 임의 사이트를 실제로 탐색하지 않습니다.

새 프로젝트에는 테스트·실측·보정 결과를 만들지 않습니다. 관련 데이터가 없는 화면은 빈 상태로 표시합니다. 샘플 프로젝트의 세션·비교 수치는 Figma 예시이며 실제 운영 지표가 아닙니다.

## 필요한 공통 연결 변경

- Sidebar: 동일한 프로젝트 조회 훅으로 목록 표시. `새 프로젝트`는 현재 경로·필터를 유지하면서 `create=1`만 추가
- AppLayout: 프로젝트 생성 모달 호스트를 연결. C03이 현재 화면 위에 뜨고 취소 시 기존 URL·본문 상태 유지. 목록 페이지의 모달과는 중복 표시하지 않음
- `findSampleProject`: 기존 샘플 조회를 유지하면서 탭에서 생성한 프로젝트도 찾도록 확장. 호출 인터페이스는 유지
- 워크스페이스 snapshot: 프로젝트 목록만 같은 공급처로 연결하여 생성 후 개수·프로젝트 행 반영
- 기존 기록·문제 테이블: 프로젝트 화면에서 중복되는 프로젝트 열·필터만 숨기는 선택적 prop 추가
- 라우트 테스트: C08·C09가 더 이상 PagePlaceholder가 아니므로 제목 확인 대상으로 변경

팀원 담당 P·R·K 페이지, persona API·MSW·새 테스트 스토어와 라우트 경로는 수정하지 않습니다. 새 프로젝트도 기존 새 테스트 진입 경로를 사용합니다.

## 로컬 확인

| 경로                                    | 화면                             |
| --------------------------------------- | -------------------------------- |
| `/projects`                             | 프로젝트 목록·검색               |
| `/projects?create=1`                    | 새 프로젝트 모달                 |
| `/?create=1`                            | 대시보드 위 새 프로젝트 모달     |
| `/projects?state=empty`                 | 프로젝트가 없는 상태와 생성 진입 |
| `/projects/banchan`                     | C06 조정안이 있는 개요           |
| `/projects/banchan?variant=unconnected` | C05 실측 미연결 개요             |
| `/projects/banchan/history`             | C08 반찬로드 진단 기록           |
| `/projects/banchan/issues`              | C09 반찬로드 발견한 문제         |

프로젝트 목록·개요의 로딩·오류는 `?state=loading`, `?state=error`로 확인합니다. 다른 쿼리와 함께 사용할 때는 `&`로 추가합니다. 세션 저장소를 지우거나 탭을 닫으면 새로 만든 데모 프로젝트가 초기화됩니다.

프로젝트 없음 미리보기는 저장된 프로젝트를 삭제하지 않습니다. 새 프로젝트의 개요는 테스트 전·실측 미연결·보정 전 상태를 반환하고 다른 샘플 프로젝트의 지표나 로그인 연결을 재사용하지 않습니다. 생성 입력 오류 시 첫 오류 입력칸으로 초점을 옮기고, 수정한 필드의 오류는 제거합니다. 저장 실패 시 폼 입력은 유지합니다.
