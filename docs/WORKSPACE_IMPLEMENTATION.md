# 워크스페이스 구현 범위

대상은 Figma W01 대시보드, W02 진단 기록, W03 발견한 문제, W04 설정, W05 시작 가이드, W07·W07b 새 테스트 시작 모달입니다. Figma 기준 화면을 React·Tailwind로 구현하고, 데이터는 독립된 더미 공급 계층으로 분리했습니다.

## 협업 경계

- 수정하는 기존 페이지는 `pages/dashboard`, `diagnosis-history`, `issues`, `settings`, `guide`의 진입 파일뿐입니다.
- 각 페이지 전용 UI는 해당 폴더의 `components/`에 둡니다.
- 두 화면 이상에서 사용하는 새 UI는 `components/Workspace/`로 한정합니다. 기존 Button, Modal, Field, Input, StatusBadge, ChoiceChip, Icon의 코드·props·스타일은 변경하지 않습니다.
- W07의 560px 크기 보정은 `.workspace-start-checks`가 있는 모달에만 적용합니다.
- 기존 레이아웃·사이드바·로그인, 라우트·경로 상수·API 클라이언트·공통 queryKeys는 이번 작업에서 수정하지 않습니다.
- 프로젝트 C 계열, 팀원 담당 P·R·K 화면과 기존 persona API·타입·mock·스토어·테스트는 수정하지 않습니다. 화면 이동만 기존 `buildPath` 경로로 연결합니다.

## 데이터와 API 연결 위치

```text
pages/*/components    화면에 필요한 데이터와 이벤트만 전달받음
hooks/useWorkspaceData.ts    TanStack Query 조회·저장 / 워크스페이스 전용 query key
apis/workspace.api.ts        현재 더미 공급 함수 / 나중에 실제 API와 응답 변환으로 교체
types/workspace.type.ts      화면에서 사용하는 데이터 계약
mocks/fixtures/workspace.ts  Figma 예시 데이터
```

- 워크스페이스 데이터는 mock 실행 여부와 관계없이 더미데이터입니다. `/api/v1`을 실제로 호출하지 않습니다.
- 더미 데이터와 persona 실행 데이터는 공유하지 않습니다. 샘플 실행 ID는 `sample-` 접두어를 사용합니다. 팀원 담당 실제 실행 화면에서는 해당 실행을 찾지 못할 수 있으며, 실제 데이터 연동 시 서버의 ID로 대체해야 합니다.
- 기간 필터는 예시 데이터 기준 시각인 `2026-11-08 14:41 KST`에 맞춥니다. 실제 API 연결 시 서버의 기준 시각으로 교체합니다.
- 예측 범위는 `[최소, 최대]`로 전달합니다. 샘플 값은 실제 사용자 이탈률·실측 결과가 아닙니다.
- 설정은 `exitplain-workspace-demo-settings` sessionStorage 키로 현재 탭에만 저장합니다. 로그인 세션·팀원 담당 스토어는 변경하지 않습니다.
- 가이드 완료 상태는 Figma 예시입니다. 실제 프로젝트 진행 조회가 준비되면 데이터로 대체합니다.

## 화면별 동작

| 화면 | 구현                                                                                                        |
| ---- | ----------------------------------------------------------------------------------------------------------- |
| W01  | 투두 요약·종이비행기 원본 에셋, 7단계 프로젝트 진행 표시, 실행 현황, 최근 문제·예측 범위, 관련 경로 연결    |
| W02  | 검색, 프로젝트·상태·유형·기간 복합 필터, URL 상태 유지, 날짜 정렬, 선택·전체 선택, 비교 조건 검증·비교 모달 |
| W03  | 원인별 개수·필터·초기화, 영향 순 정렬, 문제 상세 모달·리포트 연결                                           |
| W04  | 이름·이메일 입력, 검증, 탭 내 저장·성공 알림, 읽기 전용 실행 기본값                                         |
| W05  | 완료·현재·다음 단계 표시, 실측 분석 경로 연결, 예측과 실측 설명                                             |
| W07  | 기존 프로젝트 선택·새 프로젝트 경로 연결, 취소·닫기·Escape, 선택한 프로젝트의 새 테스트 경로 연결           |

비교는 같은 프로젝트·같은 유형·예측 결과가 있는 완료 실행 2개에서만 가능합니다. 비교 모달은 샘플 범위를 나란히 보여주며 팀원 담당 재테스트·리포트 구현을 변경하지 않습니다.

## 로컬 확인

`web/`에서 `npm.cmd run dev:mock`을 실행하고 터미널에 표시되는 포트로 접속합니다.

| 경로        | 화면                    |
| ----------- | ----------------------- |
| `/`         | 대시보드·새 테스트 모달 |
| `/history`  | 진단 기록               |
| `/issues`   | 발견한 문제             |
| `/settings` | 워크스페이스 설정       |
| `/guide`    | 시작 가이드             |

대시보드·기록·문제 화면에 `?state=loading`, `?state=error`, `?state=empty`를 붙여 상태를 확인할 수 있습니다. 오류 화면의 다시 시도는 `state`를 제거하고 재조회합니다. 검색·필터·문제 상세 상태는 별도의 쿼리를 사용하므로 서로 덮어쓰지 않습니다.

## 검증

- 새 테스트 모달에서 선택한 프로젝트 경로로 이동
- 진단 기록 복합 필터와 빈 결과 초기화, 호환 가능한 실행 비교
- 발견한 문제 원인 필터와 상세 열기·닫기
- 설정 필수값 검증과 저장
- 기존 테스트를 포함한 전체 Vitest, TypeScript·Vite build, ESLint

모달 초점 가두기·Escape·스크롤 잠금은 기존 공통 Modal 구현을 그대로 사용합니다. jsdom은 실제 브라우저 배치를 검증하지 못하므로 시각 확인은 별도로 해야 합니다.
